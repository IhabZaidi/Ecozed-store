# متجر Ecozed — صفحات هبوط للدفع عند الاستلام (الجزائر 🇩🇿)

نظام متكامل لبيع المنتجات عبر صفحات هبوط سريعة بالعربية (RTL) مع الدفع عند الاستلام.
لا توجد واجهة متجر — كل منتج له رابط مباشر (`/your-product`) يُشارك في إعلانات فيسبوك،
وينتهي باستمارة طلب + تأكيد.

## التقنيات المستخدمة

| التقنية | الدور |
|---|---|
| Next.js 16 (App Router) | الواجهات + API |
| Tailwind CSS 4 | التصميم |
| PostgreSQL + Drizzle ORM | قاعدة البيانات (منتجات، طلبات، إعدادات) |
| Meta Pixel + Conversions API | تتبع الأحداث للإعلانات |
| Microsoft Clarity (اختياري) | تسجيلات الجلسات + خرائط الحرارة — يُحمَّل عند الخمول فقط |
| Telegram Bot API | إشعار فوري بكل طلب |
| Google Sheets API | نسخة احتياطية للطلبات في جدول |
| Sharp | ضغط الصور (WebP) وتقطيع الطويلة |

## التشغيل محليًا

**المتطلبات:** Node.js 20+ (LTS) + قاعدة PostgreSQL (محلية أو Neon).

```bash
npm install
cp .env.example .env   # ثم املأ القيم (على ويندوز: copy .env.example .env)
docker compose up -d db          # قاعدة بيانات محلية جاهزة
# ...أو استعمل PostgreSQL الخاص بك واضبط DATABASE_URL
npm run db:push        # إنشاء الجداول
npm run dev            # يعمل على http://localhost:3005
```

متغيرات `.env` المطلوبة فقط: `DATABASE_URL` ،`ADMIN_PASSWORD` ،`ADMIN_SESSION_SECRET` ،`SITE_URL`
(خاص بالسيرفر، غير مكشوف للمتصفح).
البكسل وتلغرام وجوجل شيت تُضبط من لوحة الإدارة (قاعدة البيانات) — متغيرات البيئة تبقى كاحتياط فقط.

## 🚀 ابدأ متجرك الخاص في 10 خطوات

1. **شغّل محليًا** (القسم أعلاه) وافتح `/admin` بكلمة مرور `ADMIN_PASSWORD`.
2. **⚙️ الإعدادات أولًا:** املأ تبويب 📊 (Pixel ID + توكن CAPI)، ثم تبويب 🚚 (**أسعار التوصيل لكل ولاية** — بدونها لا يستطيع أي زبون الطلب!)، ثم 📲 تلغرام (جرّب زر رسالة التجربة)، ثم 📗 جوجل شيت، ثم 🔍 Clarity (اختياري).
3. **أنشئ أول منتج** (➕ منتج جديد): الاسم + الرابط + السعر + الصور، وانسخ رابطه `/your-slug`.
4. **جرّب طلبًا كاملًا** بنفسك: املأ الاستمارة → تأكد من وصول رسالة تلغرام + صف الشيت + المجموع الصحيح.
5. **راقب Test Events** في Events Manager أثناء التجربة (ضع كود التجربة مؤقتًا)، ثم **امسحه**.
6. **انشر على Vercel:** ارفع GitHub ← اربط Vercel ← أضف `DATABASE_URL` (Neon) + `ADMIN_PASSWORD` + `ADMIN_SESSION_SECRET` + `SITE_URL` (دومين الإنتاج).
7. **طبّق الجداول على قاعدة الإنتاج:** `npm run db:push` مع `DATABASE_URL` الإنتاج (أو طبّق ملفات `drizzle/`) — وإلا صفحات المنتجات ستتعطل.
8. **أنشئ Blob Store** من تبويب Storage (لصور الإدارة) وأعد إدخال الإعدادات والمنتجات على الإنتاج (أو استورد أسعار الشحن بالـ JSON).
9. **سخّن الصفحات:** افتح كل رابط منتج مرة واحدة (تجهيز نسخة ISR قبل الإعلانات).
10. **أطلق الإعلانات:** تحقق من Domain في Business Settings + الأحداث المجمّعة (Purchase أولًا)، وراقب EMQ وتغطية CAPI في Events Manager أول أسبوع.

## لوحة الإدارة (`/admin`)

الدخول بكلمة مرور `ADMIN_PASSWORD`.

- **➕ منتج جديد:** الاسم، الرابط (slug)، السعر، الصور (تُضغط تلقائيًا إلى WebP)،
  نوع الصفحة (🚀 هبوط / 📄 منتج كامل)، طريقة البيع (📦 كمية / 🎁 عروض بباقات وأسعار ثابتة + نص اختياري لكل عرض)،
  **🎬 رابط فيديو يوتيوب (اختياري)** — يُعرض قبل استمارة الطلب في صفحة الهبوط (يدعم روابط: youtube.com/watch?v=، youtu.be/، youtube.com/embed/، youtube.com/shorts/)،
  وخيار 📦 الشريط العلوي (افتح الطلبية وتأكد من الجودة وبعدها خلص) — مفعّل افتراضيًا لكل منتج.
- **الطلبات:** عرض، تغيير الحالة (📝 مسودة / 🆕 جديد / ✅ مؤكد / 🚚 تم الشحن / 📦 تم التوصيل / ❌ ملغي)،
  مع تفاصيل التوصيل (🏠 منزل / 🏢 مكتب) وسعره.
- **⚙️ الإعدادات** (4 تبويبات):
  - 📊 **بكسل فيسبوك:** الـ Pixel ID + توكن Conversions API + كود التجربة (يُمسح بعد الاختبار) + **🔍 Clarity ID** (اختياري، فارغ = لا يتحمّل شيء)، مع شرح الأحداث.
  - 📲 **تلغرام:** توكن البوت + Chat ID + زر رسالة تجربة.
  - 🚚 **التوصيل:** اسم شركة التوصيل + سعر كل ولاية (منزل/مكتب).
  القاعدة: الطريقة التي سعرها 0 أو فارغ **لا تظهر** للزبون في تلك الولاية،
  والولاية بلا أي سعر تُظهر *لا يوجد توصيل لهذه الولاية حاليًا* ويُمنع طلبها.
  خيار المكتب يظهر فقط عند وجود سعر فوق 0.
  **نسخة احتياطية:** زر ⬇️ تصدير ينزل الأسعار ملف JSON، و⬆️ استيراد يسترجعها
  على أي سيرفر — بلا إعادة إدخال.
  - 📗 **جوجل شيت:** بيانات حساب الخدمة (شارك الجدول مع بريده أولًا).

## مسار الطلب (Cash on Delivery)

1. الزبون يملأ الاستمارة → **حفظ تلقائي كمسودة** في الخلفية (بدون خطوة إضافية، وبدون أي أحداث أو إشعارات).
2. الضغط على زر الطلب → تحقق شامل ثم حفظ كطلب حقيقي → شاشة نجاح بملء الشاشة.
3. عند الحفظ: حدث `Purchase` عبر السيرفر + رسالة تلغرام + صف في جوجل شيت — كلها في الخلفية ولا تؤخر الرد.

- السعر يُحسب في السيرفر فقط (العرض يجب أن يطابق باقة معرفة، وإلا رُفض الطلب).
- التوصيل يُحسب في السيرفر حسب الولاية والطريقة؛ الولاية بلا توصيل تُظهر: *لا يوجد توصيل لهذه الولاية حاليًا* ويُمنع الطلب.
- الهاتف الجزائري بكل الصيغ: `0550…` و `+213550…` (يُحفظ موحدًا).

## أحداث فيسبوك (بدون تكرار مضمون)

| الحدث | المصدر |
|---|---|
| `PageView` | المتصفح (بمعرف فريد) + توأم السيرفر **بنفس المعرف** → يُحتسب مرة واحدة (deduplication) |
| `ViewContent` | السيرفر عند عرض الصفحة (عبر طلب داخلي عند الخمول، بهوية المتصفح كاملة) |
| `InitiateCheckout` | المتصفح (بمعرف فريد) + توأم السيرفر **بنفس المعرف** → يُحتسب مرة واحدة، مع الهاتف والعنوان مشفّرين لرفع EMQ |
| `Purchase` | المتصفح (بنفس معرف السيرفر الرسمي) + توأم السيرفر → يُحتسب مرة واحدة، مع الهاتف والعنوان مشفّرين لرفع EMQ |

المتصفح لا يرسل سوى PageView (بمعرف يُشارك مع السيرفر للمطابقة)، فاستحالة التكرار.
رقم الهاتف بصيغة E.164 مشفر + الاسم الأول والأخير + البلدية + الولاية + معرف خارجي ثابت (الهاتف)
+ `fbp`/`fbc` لرفع جودة المطابقة (Event Match Quality).
لا نجمع البريد الإلكتروني عمدًا: حقل إضافي في استمارة الدفع عند الاستلام يخسر طلبات أكثر مما تربحه نقاط المطابقة.
الاستمارات الناقصة والطلبات الفاشلة لا ترسل شيئًا.
الأحداث التي بلا أي معرف (بوتات بلا كوكيز ولا IP) تُتجاهل محليًا بدل أن ترفضها ميتا.

> **نسخة الـ API:** نستعمل `CAPI_VERSION = "v25.0"` في `lib/fb.ts` (نسخة واحدة مركزية).
> ميتا أزالت v20.0 في 2026-09-24 — عند أي تقاعد قادم يكفي تحديث هذا السطر.

> **مهم للاختبار:** ضع كود Test Event في الإعدادات أثناء التجربة وراقب الأحداث في
> Test Events، ثم **امسحه** عند الإطلاق — فبوجوده تذهب الأحداث لبيئة الاختبار ولا تُحتسب للإعلانات.
> لتلغرام: راسل البوت أولًا (Start) ثم خذ رقمك من @userinfobot.

## 🔍 Microsoft Clarity (اختياري)

تسجيلات جلسات الزوار + خرائط الحرارة (نقرات/تمرير) لاكتشاف أين يتسرب الزبائن قبل الاستمارة.

- **التفعيل:** الصق الـ Project ID في الإعدادات ← تبويب البكسل ← 🔍 Clarity ID
  (أو متغير `NEXT_PUBLIC_CLARITY_ID`). فارغ = لا يتحمّل أي شيء.
- **الأداء:** يُحمَّل عند خمول المتصفح فقط — لا يمس LCP ولا يعطّل الطلب أبدًا (أي فشل يُتجاهل بصمت).
- **الخصوصية:** فعّل إخفاء النصوص (Masking) من لوحة Clarity ← Settings، فالاستمارة تجمع أرقام هواتف.
- **المشاهدة:** clarity.microsoft.com ← مشروعك ← Recordings (تحتاج ~ساعتين لأول الجلسات).

## لماذا صفحة الهبوط سريعة؟

- بدون خطوط خارجية، وبدون مكتبات ثقيلة (JS تفاعلي = الاستمارة فقط، وتُحمَّل في حزمة منفصلة بعد الرسم).
- سكربتات الطرف الثالث (بكسل فيسبوك + Clarity) تُحمَّل عند خمول المتصفح فقط — صفر بايت في المسار الحرج.
- الصور الطويلة **تُقطع تلقائيًا** لأجزاء تُرسم من الأعلى للأسفل + صورة ضبابية فورية (~300 بايت) + أول صورة بأولوية قصوى والباقي تحميل كسول + تُقدَّم مباشرة (بدون وسيط) لسرعة LCP.
- `content-visibility` يتجاهل ما تحت الشاشة، وتخزين مؤقت سنة للصور، و`preconnect` لفيسبوك عند وجود بكسل.
- الصفحة مخزنة مؤقتًا (ISR 60 ثانية) وأحداث السيرفر لا تؤخر العرض أبدًا.

## النشر (Vercel)

- ارفع الكود إلى GitHub ثم اربط المستودع بـ Vercel.
- أضف متغيرات البيئة في إعدادات المشروع (خاصة `DATABASE_URL` لقاعدة بيانات حقيقية).
- **مهم للتتبع:** اضبط `SITE_URL` على دومين الإنتاج (يُستعمل كـ `event_source_url` لأحداث فيسبوك).
- للاختبار محليًا بدون تلويث البكسل: `DISABLE_OUTBOUND=1` في `.env` (الطلبات تُحفظ عاديًا، ولا شيء يغادر جهازك).
- الصور: نظام Vercel بلا قرص قابل للكتابة — أنشئ **Blob Store** من تبويب Storage
  (يضيف `BLOB_READ_WRITE_TOKEN` تلقائيًا) وستُرفع صور الإدارة هناك بنفس الضغط والتقطيع.

